# 医保服务目录映射台

国家与省级医疗服务项目目录的**版本映射平台**，面向跨省就医直接结算试运行。
核心纪律：**机器只出候选，人工才作决定；未映射就是未映射，任何费用都能回到当时有效的两级目录与映射决定。**

## 解决的问题

地方项目与国家项目名称相近却内涵不同：计价单位不同（次/部位/穴位/日）、省项目只覆盖国家项目的一部分、
省项目把国家明确排除的内容包进内涵，或多个省项目同时近似同一国家项目。按文字相似度自动合并会导致医院错收、基金错付。
本平台把“相似”与“等价”严格分开：

- 机器（`src/domain/matcher.js`）只产生候选、得分与风险旗标（单位不符、排除项冲突、一对多/多对一嫌疑）；
- 映射关系只能由人工通过 `MAPPING_APPROVED` 建立，必须附**专家论证、映射依据、差异说明**；
- 一对多必须给出经确认的拆账比例（合计为 1），单位换算必须人工书面确认；
- **保持未映射也是一种正式裁定（`UNMAPPED`）**：书面说明理由，系统不会把费用暗中落到最近代码。

## 事件与正式发布链

记录一经接收，标识、发生时间、版本与内容**不得原地改写**；更正一律追加后继记录（`correction_of` 指向原裁定）。

- **全局哈希链**：每个事件带 `chain_seq`、`prev_hash`、`hash`（SHA256 over 规范化信封）。
- **正式发布链**：只有权威口径发布占用连续 `release_seq` 与 `prev_release_hash`：
  `VERSION_ACTIVATED`（两级目录生效区间）、`ITEM_DISCONTINUED`（停用与替代）、
  `MAPPING_APPROVED`（人工映射裁定）、`LOCAL_RULES_PUBLISHED`（参保地规则）。
  草稿、机器候选、预检、结算类事件在全局链留痕但不占发布序号。
- 事件写入即**深冻结**；归档记录可通过 `store.load()` 逐条复核哈希与双链后重放，任何篡改都被拒绝（见 `tests/store.test.js`）。

项目保存的字段：临床内涵 `clinical_content`、排除项 `exclusions`、计价单位 `pricing_unit`、
适用机构 `applicable_institutions`、支付条件 `payment_conditions`（含事前备案要求）、
省项目另存必备材料 `required_materials` 与组合要求 `required_combo`。
裁定保存：专家论证 `expert_review`、映射依据 `mapping_basis`、差异说明 `difference_note`、
单位换算确认 `unit_conversion`、生效区间、`correction_of` 更正关系。

## 结算口径（关键规则）

1. **按服务发生日**选择当时有效的国家目录、就医地省目录、映射裁定与**参保地**规则；提交日再晚也不改口径。
2. 结算时把每一条费用的依据**固化**进账单事件：两级目录的发布事件编号、发布序号、哈希及项目内容快照，
   映射裁定编号与论证依据，参保地规则版本编号。任何费用都可逐字段回溯。
3. 支付计算遵循参保地规则：甲类按比例、乙类先行自付、丙类全自费、超限价自付、缺事前备案材料的份额不支付；
   一对多按专家确认 `share` 拆账后各自适用规则；金额以“分”整数运算。
4. **医院提交前预检**：阻断材料缺口、计价单位不符、适用机构不符、项目停用、无人工映射、
   未映射项目、多省项目同映一个国家项目（重复收费嫌疑）、国家排除项被另行收费等；可留痕为 `CLAIM_PRECHECKED`。
5. **患者账单说明**（`explainSettledLine`）：逐项写明项目来源目录、映射决定与差异、自付理由、对应发布事件编号。
6. **发布后更正**：`CLAIM_ADJUSTED` 用最新发布链口径重算**仅未终结**账单行并产生差额；
   已 `CLAIM_LINE_FINALIZED` 封存的账单行永远保持原口径。无差额不写事件。

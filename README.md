# 医保服务目录映射台

国家与省级医疗服务目录的**版本映射平台**。面向跨省就医结算试运行：名称相近但内涵不同的地方项目（计价单位不同、只覆盖国家项目的一部分、打包/拆分关系）只由机器给出候选，由人工裁定并写明差异；结算始终回到**服务发生日**有效的两级目录、映射决定与参保地规则。

纯 Node.js 实现，无外部依赖，事件溯源（event sourcing）。

## 核心红线

1. **机器只给候选，人工才落码。** 一对多、多对一、部分重叠只能出现在候选里；生效映射必须由人工批准，且非全等映射必须写差异说明与映射依据。
2. **未映射就是未映射。** 没有生效的人工决定时，结算直接阻断（`UNMAPPED`），不会暗中回退到名称最近似的编码。
3. **以服务发生日为准。** 国家目录、就医地省级目录、参保地规则、映射决定都按服务发生日的时点取版本，并在账单提交时钉死引用。
4. **更正只影响未终结账单。** 发布后更正按服务日重算 open 账单产生差额；已封存（sealed）账单拒绝调整，提交时的原口径原样可查。
5. **记录不可原地改写。** 更正、修订、停用都以新事件和新版本表达；仓库事件编号首尾相扣，历史被改动会在重载时被哈希链识破。

## 领域资料范围

| 路径 | 内容 |

| `tests/` | 22 项契约与领域测试 |

## 发布链模型

每条事件携带：

```jsonc
{
  "event_id": "E000042",            // 仓库统一编定的事件编号
  "seq": 42,                         // 全局发布序号，连续递增
  "prev_event_id": "E000041",        // 前一条事件（首条为 null）
  "chain_hash": "<sha256>",          // 对本事件规范表示（除该字段）的哈希
  "aggregate_type": "national_item",
  "aggregate_id": "item:national:N-MRI-001",
  "version": 2,                      // 聚合内连续版本号
  "occurred_at": "2026-10-02T09:00:00+08:00",
  "event_type": "CATALOG_CORRECTED",
  "actor": { "id": "U-ADMIN-01", "name": "目录管理经办", "role": "catalog_admin" },
  "payload": { /* 按事件类型区分 */ }
}
```

事件类型：`CATALOG_DRAFTED`、`CATALOG_REVISED`、`CATALOG_CORRECTED`、`VERSION_ACTIVATED`、`ITEM_DISCONTINUED`、`RULE_PUBLISHED`、`MAPPING_PROPOSED`、`MAPPING_APPROVED`、`MAPPING_REJECTED`、`MAPPING_DEACTIVATED`、`CLAIM_PRECHECKED`、`CLAIM_SUBMITTED`、`CLAIM_SEALED`、`CLAIM_ADJUSTED`。

- 生效区间统一为半开 `[effective_from, effective_to)`；修订生效自动把旧版本收口，激活导致区间重叠会被拒绝。
- 停用（`ITEM_DISCONTINUED` / `MAPPING_DEACTIVATED`）可携带替代引用；停用日当天仍有效，次日失效。
- 更正（`CATALOG_CORRECTED`）以新版本进入版本链并可追溯生效；被更正版本内容原样保留，仅状态标记为 `corrected`。
- 投影器（目录、规则、映射、账单）注册在事件存储上：写入前先试探性投影，业务规则失败则整条事件回滚拒收。

## 映射裁定

| 裁定类型 | 含义 | 结算要求 |
| --- | --- | --- |
| `EXACT` | 临床内涵、排除项、计价单位、适用机构全等 | 直接按国家项目结算 |
| `PARTIAL_OVERLAP` | 只覆盖国家项目内涵的一部分（如耗材并入操作费） | 必须申报重叠计费比例 `billable_portion`，范围外费用自付 |
| `ONE_TO_MANY` | 省项目打包对应多个国家单项 | 必须按国家项目分别申报数量/单价（`allocations`） |
| `MANY_TO_ONE` | 多个省项目共同构成一个国家项目 | 必须组合申报且恰好一行 `primary`，其余 `component` 基金不重复支付 |

人工批准只能在机器给出的候选范围内选择国家项目；非全等裁定必须写 ≥10 字的差异说明，并保留 `mapping_basis.documents`（论证文件、比对底稿等）。拒绝候选（`MAPPING_REJECTED`）后项目保持未映射。

## 结算流程

1. **预检 `CLAIM_PRECHECKED`**：医院提交前看到全部阻断项——停用/替代编码、未映射、计价单位不符、适用机构不符、材料缺口、一对多缺拆分、多对一主计行不唯一等。预检通过且账单指纹（`draft_hash`）与提交时一致，才允许提交。
2. **提交 `CLAIM_SUBMITTED`**：逐行解析并钉住省项目版本、国家项目版本（可沿更正链平移）、映射决定、参保地规则版本，记录费用拆分与每一条自付理由。
3. **封存 `CLAIM_SEALED`**：账单口径冻结。
4. **更正差额 `CLAIM_ADJUSTED`**：更正发布后只对 open 账单按服务日重算；每行保留调整前后引用、差额、重算后金额与新的自付理由。若更正后该行不再合规（如映射停用），记 `REVOKED`，基金已付部分全额追回。

患者账单说明（`explainClaim`）对每一行费用给出：就医地省项目版本、国家项目版本、映射决定（类型/差异说明/专家依据文件）、参保地规则版本、总费/基金/自付金额与逐条自付理由——任何费用都可追溯到当时有效的两级目录及映射决定。

## 试运行场景

`src/scenario.js` 构造了典型陷阱（就医地浙江 330000，参保地北京 110000，服务日 2026-09-15）：

- `P33-MRI-01` → `N-MRI-001`：全等；
- `P33-BX-01` → `N-BX-003`：省项目把穿刺针耗材并入操作费，国家项目排除耗材 → 部分重叠；
- `P33-HX-01` → `N-HX-006` + `N-HX-007`：按日打包对应两个单项 → 一对多；
- `P33-NEU-01/02` → `N-NEU-008`：脑电图/肌电图两行合成一个台次项目 → 多对一；
- `P33-O2-01`（吸氧日包）vs `N-O2-004`（按小时）：名称像但计价单位不同，人工拒绝，保持未映射；
- `P33-OLD-09`：已停用并指向替代编码；
- 2026-10-02 发布国家目录内涵更正与参保地规则修订（追溯至 09-01），演示 open 账单差额与 sealed 账单冻结。
